# IconMasterLite 完整接档说明

## 1. 项目目标

实现一个接近软媒 PCMaster / IconMaster 操作逻辑的绿色 Windows GUI 小工具。用户可以打开程序后把文件拖入窗口，也可以直接把文件拖到 `IconMasterLite.exe` 本体上；程序在输入文件原目录自动完成图片、ICO、EXE 图标之间的转换或提取。

## 2. 当前版本

- 版本：1.2.0
- 形态：原生 Win32 GUI
- 源码：C++17
- 构建：CMake + MSVC，Win32 Release
- 外部依赖：无第三方运行库
- MSVC CRT：Release 默认 `/MT` 静态链接
- 图像编解码：Windows Imaging Component（WIC）
- 程序图标：`res/IconMasterLite.ico`，通过 RC 嵌入 EXE
- 文本格式：UTF-8 + CRLF

## 3. 已确认架构

### 3.1 输入入口

有两个输入入口，最终都调用同一个 `ProcessPath()`：

1. GUI 窗口 `WM_DROPFILES`
2. Windows Explorer 把文件拖到 EXE 本体后产生的命令行参数

这样不会出现窗口拖放和 EXE 拖放行为不一致的问题。

### 3.2 图片 → ICO

- 输出：原目录、原 basename、扩展名替换为 `.ico`
- 已存在：覆盖
- 尺寸：16 / 20 / 24 / 32 / 40 / 48 / 64 / 96 / 128 / 256
- 保持宽高比
- 非正方形输入透明补边并居中
- ICO 内图像帧采用 PNG 数据并保留 Alpha

### 3.3 ICO → PNG

- 读取 ICO 全部帧
- 按 `width × height` 选择最大帧
- 输出原目录同名 `.png`
- 已存在：覆盖

### 3.4 EXE → ICO

- 使用 `LoadLibraryEx(..., LOAD_LIBRARY_AS_DATAFILE | LOAD_LIBRARY_AS_IMAGE_RESOURCE)` 仅映射资源，不执行目标 EXE
- 枚举第一个 `RT_GROUP_ICON`
- 根据组目录引用读取各个 `RT_ICON`
- 重写标准 ICO 的 ICONDIR / ICONDIRENTRY
- 保留该图标组中的实际多尺寸图像资源

## 4. GUI 与系统行为

- 原生 Win32 / GDI / WIC / COM
- 支持一次拖入多个文件
- 结果列表显示处理成功/失败
- Per-Monitor V2 DPI awareness；旧系统回退 `SetProcessDPIAware`
- 不写注册表
- 不生成用户配置目录
- 处理完成后窗口保留，可继续拖入文件

## 5. 程序图标与资源

### 5.1 文件

- `res/IconMasterLite.png`：1024×1024 PNG 母版
- `res/IconMasterLite.ico`：Windows 多尺寸 ICO
- `res/resource.h`：`IDI_APP_ICON`
- `res/app.rc`：ICON 与 VERSIONINFO

### 5.2 编译路径

`CMakeLists.txt` 使用 `LANGUAGES CXX RC`，并把 `res/app.rc` 作为 `IconMasterLite` 的源文件。Visual Studio 生成器会调用 Windows Resource Compiler，最终资源直接写入 EXE。

`WNDCLASSEXW::hIcon / hIconSm` 也显式加载 `IDI_APP_ICON`，因此：

- Explorer 中 EXE 有正式图标
- 窗口标题栏使用正式图标
- 任务栏使用正式图标

不要求运行时把 ICO 放在 EXE 旁边。

## 6. 本轮修复

### 6.1 MSVC 19.51 `std::max` 编译错误

旧代码把 `RECT::right/bottom` 的 `LONG` 与 `int` 常量直接传入 `std::max()`，MSVC 19.51 无法推导同一个模板类型。

当前修复：

- 先把客户区宽高显式规范化为 `int`
- 再计算 `listWidth/listHeight`
- `MoveWindow()` 使用标准 6 参数调用

### 6.2 重复宏警告

`WIN32_LEAN_AND_MEAN` 与 `NOMINMAX` 只由 CMake 的 `target_compile_definitions` 提供，`main.cpp` 不再重复 `#define`。

### 6.3 EXE 本体拖放

旧 v1.1.0 包虽然文档声称支持，但源码实际上没有读取命令行文件参数。本版已补齐 `CommandLineToArgvW(GetCommandLineW(), ...)`，并在窗口创建、显示完成后处理 `argv[1..]`。

## 7. 换行规范

用户要求编译用文件采用 CRLF。本版已对以下文本文件统一使用 UTF-8 + CRLF：

- `.cpp`
- `.h`
- `.rc`
- `.bat`
- `.md`
- `CMakeLists.txt`

并加入 `.gitattributes` 固定规则。PNG/ICO/ZIP 属于二进制文件，不涉及换行。

## 8. v1.2.1 窗口居中规则

用户项目级 UI 规则：今后制作的软件窗口默认应在屏幕中央打开。IconMasterLite 已落实如下：

- 程序启动时通过 `GetCursorPos` + `MonitorFromPoint` 选择鼠标所在显示器；无法读取鼠标位置时回退主显示器。
- `CreateWindowExW` 创建窗口后暂不显示，先调用 `CenterWindowOnMonitor()` 按该显示器 `MONITORINFO::rcWork`（排除任务栏后的工作区）计算中心位置。
- 使用 `SetWindowPos(..., SWP_NOSIZE | SWP_NOZORDER | SWP_NOACTIVATE)` 完成定位，然后才 `ShowWindow`，避免启动时从默认位置闪动到中央。
- 直接把文件拖到 `IconMasterLite.exe` 启动时也经过同一启动路径，因此同样居中。
- `WM_DPICHANGED` 时先接受系统建议的新窗口尺寸，再按建议矩形对应的新显示器重新居中，保证跨 DPI 显示器时位置正确。
- 这不是“锁定窗口在中央”：程序打开后用户仍可自由移动窗口。

## 9. 当前已知边界

1. EXE 当前只提取第一个 `RT_GROUP_ICON`；多图标组程序暂不提供选择器。
2. ICO→PNG 当前只导出最大帧。
3. 图片输入依赖系统 WIC codec；WebP/AVIF 等是否可读取决于系统组件。
4. 图片→ICO 内部帧使用 PNG-compressed ICO，目标为现代 Windows。
5. GUI 当前同步处理；普通图标转换足够快，若以后做大量超大图片批处理再考虑工作线程。
