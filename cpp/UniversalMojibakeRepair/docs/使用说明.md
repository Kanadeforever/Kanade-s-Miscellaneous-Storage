# 万能乱码恢复 v0.2.0 使用说明

## 1. 最常用：恢复百分号编码的文件名

把下面的完整文字直接复制到上方输入框：

`NPCSubtitles_v0.1e-log1_%E6%8C%89%E9%9C%80%E8%AF%A6%E7%BB%86%E6%97%A5%E5%BF%97_%E5%B7%B2%E7%BC%96%E8%AF%91%E5%AE%8C%E6%95%B4%E5%B7%A5%E7%A8%8B%E5%8C%85_20261011.zip`

点击 **自动分析并恢复**，或在第三行的 **表示形式** 下拉框选「URL 百分号编码（%XX / UTF-8）」后点击 **格式解码**。结果是：

`NPCSubtitles_v0.1e-log1_按需详细日志_已编译完整工程包_20261011.zip`

**注意**：这只转换文字内容，不会自动改名磁盘上的 ZIP，也不代表可以拖入 ZIP 文件。文件拖放仍只接受单个 TXT。

## 2. ASCII / 中文字节互转

在「表示形式」选择「ASCII / UTF-8 十进制字节」：

- 输入 `ABC`，点击「格式编码」得到 `65 66 67`。
- 输入 `65 66 67`，点击「格式解码」得到 `ABC`。
- 输入 `中文`，点击「格式编码」得到 `228 184 173 230 150 135`。
- 想得到十六进制，则选择「ASCII / UTF-8 十六进制字节」；中文对应 `E4 B8 AD E6 96 87`。

严格来说 ASCII 只表示 U+0000～U+007F；中文部分使用 UTF-8 字节，不能误以为中文有单个 ASCII 数值。也可以选择「Unicode 码点（U+XXXX）」实现 `中文` ↔ `U+4E2D U+6587`。

## 3. 其他可选表示形式

| 模式 | 输入示例 | 格式解码结果 |
|---|---|---|
| URL 百分号 | `%E4%B8%AD%E6%96%87` | 中文 |
| 表单编码 | `A+B%20C` | A B C |
| HTML 实体 | `&#x4E2D;&#x6587;` | 中文 |
| JS/Unicode 转义 | `\u4E2D\u6587` | 中文 |
| 十进制字节 | `228 184 173 230 150 135` | 中文 |
| 十六进制字节 | `E4 B8 AD E6 96 87` | 中文 |
| Unicode 码点 | `U+4E2D U+6587` | 中文 |
| Base64 | `5Lit5paH` | 中文 |
| Quoted-Printable | `=E4=B8=AD=E6=96=87` | 中文 |

每个格式都有「格式解码」「格式编码」两个方向。转换操作始终读取**上方输入区**，将结果写到**下方输出区**。要再次转换输出结果，可先复制到输入区再按下一步；自动分析对明确的多层转义最多连续尝试三轮。

## 4. 传统代码页乱码恢复

例如 `æ–‡å­—` 可能来自 UTF-8 被错误按 CP1252 打开。先按「自动分析并恢复」查看候选；若需要手动，使用第二行两个下拉框选择「乱码当前被当作」和「原字节实际编码」，再按「手动恢复」。这里需要对编码错误有一定认识；候选评分不是对语义正确性的绝对保证。

## 5. TXT 文件打开及拖放

单个 `.txt` 可以通过「打开 TXT」、拖入窗口，或拖到 EXE/快捷方式上打开。读取后自动分析并显示候选；不接受多个文件、文件夹和其他扩展名。TXT 默认只读进入编辑区，结果要由用户自己点击「保存结果」导出 UTF-8；不会自动覆盖原文件。

## 6. 长文章与安全边界

可以输入很长的段落或文章，没有 260 字句长上限；实际规模仍受内存和 Windows RichEdit 控件限制。自动代码页搜索以片段分析后处理全文，避免把数千种方案逐一应用于整个文章。若原文字节已被替换成问号、U+FFFD、删除或截断，则不能保证恢复。非法 UTF-8 解码会保留原始 `%XX` 或提示失败；不生成一个看似完整的错误译文。

## 7. UI 规则

静态标签文字背景与窗口一致；编码说明分为「乱码当前被当作：」「原字节实际编码：」，避免压缩而看不全。下方第三行是「表示形式」和格式双向转换按钮。窗体可拖动改变大小，图标已嵌入程序资源。若窗口在实际 DPI 下仍有截断，请提供 Windows 缩放百分比及截图。
