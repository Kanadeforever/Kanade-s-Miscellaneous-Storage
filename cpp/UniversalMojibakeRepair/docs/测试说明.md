# 万能乱码恢复 v0.2.0 测试与验收说明

## 一、已经实际执行的算法回归

执行环境：Linux / GCC / C++17；命令：

```bash
g++ -std=c++17 -Wall -Wextra -Wpedantic tools/test_transform.cpp src/TransformEngine.cpp -O2 -o test_transform
./test_transform
```

已验证：

1. 给出的 `NPCSubtitles...%E6...zip` 实际文件名百分号解码，并由自动候选正确识别。
2. 标准 ASCII `ABC ↔ 65 66 67`，中文 UTF-8 `中文 ↔ 228 184 173 230 150 135`。
3. 十六进制分隔格式及连续格式与中文双向转换。
4. HTML5 命名/数值/组合实体，Unicode/JS 转义、代理对表情符号、Unicode 码点。
5. Base64、Quoted-Printable、普通 URL 百分号、表单 `+` 语义。
6. 两层 URL 百分号 → HTML 数值实体自动恢复；普通文件名不会被误判成候选。
7. 汉字、拉丁、日文、俄文、阿拉伯文、emoji 的所有格式双向往返。
8. 非法 ASCII 字节 256、非法 UTF-8、非法 Base64 必须拒绝。
9. 约百万字符长文执行 URL、HTML、ASCII 数字字节双向往返。

**测试结论**：上述纯格式模块回归实际通过。它不替代 Windows GUI/代码页引擎的编译、运行和交互验收。

### 构建工具链与中文路径隔离（待 Windows 实机复测）

已经收到一次 Win32 实机失败日志：MSVC 19.51 测试文件编译成功，CMake 4.4 / NMake 在资源与清单链接阶段失败；其中 `CMAKE_MT-NOTFOUND` 且 `rc` 无法运行。新的 `build.bat` 在 CMake 之前检查四项工具 `cl.exe`、`nmake.exe`、`rc.exe`、`mt.exe`，不完整时尝试 Visual Studio `vcvars64.bat`，仍不可用则明确提示安装 Windows 10/11 SDK。

后续实机日志确认 Windows SDK 工具均可找到，资源编译成功；新增失败发生在 MSVC 链接命令中，包含中文的 `/pdb:` 路径出现乱码并返回 `Unknown system error -1`。构建脚本现改为临时 `subst` 映射项目根目录，使 CMake、NMake、MSVC 路径均只含 ASCII 字符。映射盘符会在正常完成或报错退出时撤销，原目录中保留 `.build` 错误现场。

本轮已完成静态脚本与项目结构检查，但未在用户 Windows 环境实跑 BAT。下次复测应确认：工具缺失时给出 SDK 专项错误；补齐环境后重新开始 CMake 检测并避免读取旧失败缓存；链接命令中的 `/pdb:` 必须只包含映射盘符下的 ASCII 路径；正式 EXE 应出现在原项目 `release` 目录；最终 GUI 和格式回归测试实际通过才算构建完成。

## 三、验证边界与待补项

- 本执行环境无 Windows SDK / MSVC / MinGW-w64 Windows 交叉编译器，因此 **没有实际 Windows EXE 编译成功记录**。
- 静态代码审查不能代替 Win32 链接和显示测试，遇到任何编译错误需以完整构建日志为准。
- HTML5 名称表采用**带分号**的 2125 项；尚不支持旧浏览器的无分号容错规则。
- 当前百分号格式使用严格 UTF-8，不自动猜测 GBK/Big5 原始百分号字节。
- `?` / U+FFFD 代表可能有信息损失；不能声称可无损恢复。
