# 万能乱码恢复 v0.2.0 构建与发布说明

编译入口是 `source\UniversalMojibakeRepair\build.bat`，工程详细说明是旁边的 `readme.md`。构建系统使用 CMake 3.20 及以上版本、Visual Studio / Build Tools 的 MSVC x64、Windows SDK；脚本自动查找工具，不写死开发机的绝对路径。**Win32 构建同时要求 `rc.exe`（资源编译器）和 `mt.exe`（清单工具），仅有 `cl.exe` 不够。**

**自动流程**：`chcp 65001 >nul` → 检查 `cl.exe` / `nmake.exe` / `rc.exe` / `mt.exe`，必要时通过 `vcvars64.bat` 恢复 Windows SDK 环境 → 识别 CMake / CTest → `subst` 映射空闲盘符作为纯 ASCII 构建路径 → 清理失败的 `.build\msvc-x64` 缓存 → 生成 NMake Release → 编译原生 Win32 GUI + `TransformRegression` → 运行 CTest → 拷贝 `release\万能乱码恢复.exe` → 成功时清理中间目录 → 成功或正常报错退出时撤销本次盘符映射。失败时中断发布并保留 `.build` 现场供定位。

`src\Resource.rc` 编译时从 `config\AppIcon.ico` 嵌入 Win32 图标。`Comdlg32` 实现文件选择，`Shell32` 实现文件拖放与命令行读取；RichEdit 使用 Windows 系统自带 `Msftedit.dll`。正式运行无需 Python、Node.js、Qt、MFC 或其他旧版本项目文件。

在当前 Linux 环境可以单独构建测试 `tools/test_transform.cpp + src/TransformEngine.cpp`，但**不等于已构建 Win32 EXE**；正式包中 `release/` 空目录用于保证结构完整，Windows 构建后填入可执行文件。

代码文件以英文命名，中文注释解释操作与约束；所有文本文档、C++、CMake、BAT 必须为 UTF-8 无 BOM + CRLF，批处理带文字的 `rem` 和 `echo` 行尾加两个半角空格。成功构建后，请用 Windows 实机验证图标、拖入 TXT、界面 DPI 与格式解析。打包时四目录均必须保留。

## Windows 中文路径兼容与自动映射

构建脚本由 `%~dp0` 进入脚本目录，再通过 `pushd "..\.."` 和 `%CD%` 获取真实工程根目录；不能把 `%~dp0`（带尾部反斜杠）直接作为 CMake 的源码参数，否则可能造成引号与后续 `-B/-G` 参数合并。

最新用户日志表明，MSVC 19.51 已编译测试文件，Windows SDK 的 `rc.exe`/`mt.exe` 已恢复，但 `link.exe` 收到的 `/pdb:` 绝对路径显示中文乱码，链接报 `Unknown system error -1`。因此本构建入口在调用 CMake 之前尝试用 `subst` 为整个工程目录映射空闲盘符，让 `-S`、`-B`、`/pdb:` 和中间文件都以纯 ASCII 路径呈现。原始文件夹名称、目录组织和正式发行位置都不需要更改；不复制工作目录，也不触碰用户已有的盘符映射。

正常完成或报错时映射会自动撤销。遇到断电、强制终止 CMD 等非正常退出，则可通过 `subst` 查找残留映射，并只删除确认为当前项目创建的映射。工具链检查仍然保留；中文路径隔离不能替代 Windows SDK 或 Visual Studio C++ 组件。

`tools/verify_project.py` 会检查临时映射是否在 CMake 前建立，以及成功与失败路径均具有清理步骤。此修复不改 GUI、文本转换及编译产物内容。**Windows 实机重试之前，只能宣称方案已静态验证，不能宣称已构建成功。**

## Windows SDK 工具链不完整时的处理

用户实机日志已出现：MSVC 19.51 能编译 `testCXXCompiler.cxx`，但 CMake 在链接阶段调用 `rc` 失败，同时输出 `CMAKE_MT-NOTFOUND`。这明确表示 **当前构建环境未能使用 Windows SDK 的 `rc.exe` / `mt.exe`**；尚不能单凭日志判定 SDK 是根本未安装还是 PATH 初始化不完整。

修正版 BAT 会检查 `where rc.exe`、`where mt.exe`；工具缺失时先重新运行 Visual Studio 的 `vcvars64.bat`。如果依然缺失，提示通过 Visual Studio Installer 的“修改 → 单个组件”安装 Windows 10/11 SDK，并停止构建。工具齐备后清除旧 `.build\msvc-x64`，避免保留 `CMAKE_MT-NOTFOUND` 缓存。

用户也可在 VS x64 开发者命令提示符中手动执行 `where cl.exe`、`where nmake.exe`、`where rc.exe`、`where mt.exe` 辅助定位。如果四项均能找到，但仍在链接阶段报错，需继续提供新的完整日志。**当前环境没有 Windows SDK/MSVC，尚不能宣称本批处理已在 Windows 实机上成功完成构建。**

## 中文路径链接错误补充记录

第二份 Windows 日志中 `RC Pass 1` 成功，`CMAKE_MT-NOTFOUND` 已消失，说明此前 Windows SDK 的可见性故障已经排除。后续 `LINK Pass 1` 失败时，`/pdb:` 路径中的中文片段出现替换乱码字符。当前把这项错误独立归类为**构建路径编码疑似不兼容**，优先采用临时 ASCII 盘符方案隔离，不能继续误报 SDK 缺失。此结论仍待新的 Windows 编译结果确认。
