# Explorer Rescue v0.2.7 完整接档说明

## 1. 项目目标

解决 Windows 11 File Explorer 偶发卡死后，常规重启 `explorer.exe` 会丢失全部已打开窗口/标签页的问题。

核心验收标准不是“重新打开相同数量的目录”，而是：

- 原窗口数量尽量恢复；
- 每个窗口原本属于它的标签页仍组合在同一个窗口；
- 标签路径正确；
- 不能把失败标签留成一堆“此电脑”并判成功；
- 最小化窗口不能恢复成异常小窗口；
- 后台资源占用极低；
- 绿色、无注册表、无日志、无网络；
- 持久运行文件严格只有 EXE / config.ini / sessions.dat。

## 2. 用户入口

### 第一次运行

`ExplorerRescue.exe` 进入后台守护、不主动重启 Explorer，并立即开始第一次完整扫描。

### 已有守护实例

再次运行 `ExplorerRescue.exe` -> 发送本地消息给守护实例 -> 执行救援。

### 热键

`Win + Shift + E` -> 与再次运行 EXE 完全相同。

### 托盘

运行后显示 Explorer Rescue 托盘图标：

- 双击：重启并恢复资源管理器；
- 右键：重启并恢复、立即扫描并保存、查看扫描状态、退出；
- Explorer 重启后通过 `TaskbarCreated` 自动重新注册托盘图标。

### 后台守护意外不存在 + Explorer 已卡死

新进程检测 `sessions.dat` 存在有效历史且 Explorer 无响应时，会直接进入救援，再继续作为守护实例。

## 3. 周期扫描

配置：

```ini
[Scan]
IntervalSeconds=5
TimeoutMilliseconds=20000
```

### v0.2.7 正式捕获基线：逐项等价 Mine_Exp

`CaptureExplorerSnapshot()` 不再自行推导额外的 Explorer 规则，而是按用户已经实机验证的 Mine_Exp `get_open_windows()` 语义：

1. `Shell.Application.Windows()`；
2. 遍历每个 `w`；
3. `w.Document`；
4. `w.Document.Folder.Self.Path`；
5. `w.HWND`；
6. 同 HWND 直接归为同一个标签组；
7. 保存路径。

与 Mine_Exp 一样，单个条目临时没有 Document/Folder/Self/Path/HWND 时跳过该条目，而不是让整个守护器永久停止。

明确删除旧版新增但未经 Mine_Exp 验证的限制：

- 不要求 HWND class 必须为 `CabinetWClass/ExploreWClass`；
- 不读 `FullName` 作为 Explorer 身份门槛；
- 不要求 Shell.Windows Count 枚举前后完全一致；
- 不要求连续两次扫描的 HWND/路径集合完全一致；
- 不要求 `GetWindowPlacement()` 成功才能保存路径。

`WINDOWPLACEMENT` 仅作为附加数据；失败则 `hasPlacement=false`，恢复时按主显示器工作区中央的常规尺寸兜底。

### COM ABI 修复

旧版 `winmini.h` 手写 `VARIANT` 只有 16 字节。Windows x64 官方 VARIANT 需要容纳 BRECORD 的两个指针字段，实际 ABI 尺寸为 24 字节。旧结构会让 `IDispatch::Invoke` 写回结果时越界/错位，可能直接造成 `Document/Folder/Self/Path` 或 HWND 读取异常。

v0.2.7 增加 16 字节 union 容量并固定：

```cpp
static_assert(sizeof(VARIANT) == 24);
```

这是一项底层正确性修复，不只是扫描策略调整。

## 4. 扫描暂停

扫描失败或超时时：

- `g_scanPaused = 1`；
- epoch 自增，使已经跨越故障边界的旧扫描结果不可写回；
- 当前扫描令牌立即作废；即便一个旧 COM 扫描线程稍后才返回，也不能清除新扫描 busy 状态或覆盖新历史；
- 周期定时器仍存在，但 StartPeriodicScan 直接返回，不再访问 Shell；
- 使用 `Shell_NotifyIconW(NIF_INFO)` 发送 Windows 系统通知，不再绘制自定义通知窗口；
- 历史文件保持原样。

恢复完整成功后才清除 paused 并重新启动扫描。

## 5. sessions.dat 五槽格式

固定：5 slots × 512 KiB，最大约 2.5 MiB。

每个槽：

- 64-byte slot header；
- 后续为一个 ERSNAP2 serialized snapshot。

slot header 包含：

- magic/version/header size；
- generation；
- capture FILETIME；
- payload bytes；
- window count；
- tab count；
- payload hash；
- header hash。

写入：

1. 选择无效槽；如果 5 个都有效则选择 generation 最旧槽；
2. 先写 payload；
3. FlushFileBuffers；
4. 最后写 slot header；
5. 再 FlushFileBuffers。

若中途崩溃，该槽 hash 校验失败，其余槽不受影响。

完全相同 content hash 不重复写入，因此保留 5 个“不同的有效状态”而不是快速被同一状态刷满。

读取总是从所有有效槽中选 generation 最大者。

## 6. 主动重启保护

Explorer 响应正常时：

1. 停止接受新的后台扫描结果（epoch）；
2. 等待当前扫描短暂收尾；
3. 启动同一个 ExplorerRescue.exe `/capture-once` 子进程；
4. 子进程执行严格稳定捕获并直接安全写入 sessions.dat；
5. 父进程等待独立扫描超时 + 5s 收尾余量；
6. 子进程超时可以 TerminateProcess，不会损坏守护进程；
7. 最终捕获失败且 Explorer 仍响应 => 取消重启；
8. 最终捕获成功 => 使用最新有效历史重启/恢复。

这个设计不需要任何临时文件。

## 7. 卡死救援

Explorer 无响应时：

- 不做最终 Shell COM 捕获；
- 直接 `LoadLastSnapshot()`；
- 若没有任何有效历史，拒绝强杀 Explorer；
- 有历史则结束当前用户 session 内的 explorer.exe；
- 启动新 Explorer Shell；
- 等待 Shell_TrayWnd 可响应；
- 恢复窗口与标签组。

若扫描此前已经因为障碍暂停，用户触发救援也会直接使用最近有效历史，不会再被失败扫描阻塞。

## 8. 标签恢复

参考 Mine_Exp：

- 相同 Explorer HWND = 同窗口标签组；
- 首标签通过 Shell.Open/Explore 建立窗口；
- 等待 `ShellTabWindowClass`；
- `WM_COMMAND / 0xA21B` 创建标签；
- 枚举同 HWND ShellWindows；
- 使用 COM IUnknown identity 差异识别新标签；
- Navigate2 到目标路径；
- 每个标签导航后验证真实位置；
- 失败标签尝试关闭；
- 最终整组重新枚举校验；
- 仍失败则关闭本轮创建窗口并整组再建一次。

禁止把标签失败静默降级成独立窗口，因为这会破坏用户要求的标签组合关系。

## 9. 窗口 placement

捕获使用 `GetWindowPlacement()`。

恢复使用 `SetWindowPlacement()`。

不再把最小化时的 Left/Top/Width/Height 当作普通矩形。

`PlacementUsable()` 检查：

- 正常还原尺寸；
- 是否仍有有效显示器；
- 与工作区有足够交集。

无效时：

- 主显示器工作区；
- 约 1200×800 DPI 缩放；
- 上限约工作区 85%；
- 工作区中央。

## 10. 运行时文件

只允许：

```text
ExplorerRescue.exe
config.ini
sessions.dat
```

没有：

- data\
- logs\
- session.tmp
- session.bak
- vbs
- Startup 文件
- 注册表键
- AppData fallback

## 11. 资源策略

- 原生 x64 Win32；
- /NODEFAULTLIB；
- 仅 Windows 系统 DLL；
- 无 .NET / Qt / WebView2；
- 空闲消息循环 + 托盘图标 + Timer + RegisterHotKey；
- 扫描线程 64 KiB stack reservation；
- 恢复线程 128 KiB stack reservation；
- 无变化不写 sessions.dat；
- 无日志；
- 无网络。

## 12. 当前静态验证

构建环境已完成：

- x86-64 PE GUI 链接；
- 图标 + PerMonitorV2 manifest 内嵌；
- import table 检查；
- 无 .NET/Qt/CRT 动态依赖；
- 源码 `-Wall -Wextra` 交叉编译无警告；
- 原子状态操作使用 MSVC/clang-cl 的 `_Interlocked*` 编译器 intrinsic，x64 下直接生成原子指令，不从 Kernel32 导入 Interlocked 符号，避免装载阶段入口点解析问题。

当前容器不是 Windows 11，因此 Explorer 标签页真实动态恢复仍必须以用户实机为最终验收。


## v0.2.1 修复

- 修复 v0.2.0 在部分 Windows 环境启动时出现“无法定位程序输入点 InterlockedCompareExchange”的 Loader 级错误。
- `_InterlockedCompareExchange/_InterlockedExchange/_InterlockedIncrement` 改为编译器 intrinsic，最终 PE 导入表不再包含三个 Interlocked 符号。
- 首次生成 `config.ini` 的默认扫描间隔由 15 秒改为 5 秒；合法范围仍为 5~600 秒。
- 其余会话历史、扫描暂停、重启与标签组恢复逻辑不变。


## v0.2.2 修复

- 修复 v0.2.1 首次扫描容易被 5000 ms watchdog 误判超时的问题：默认独立扫描超时改为 20000 ms，合法范围 10000~120000 ms。
- 周期扫描间隔继续默认 5 秒；扫描间隔与扫描超时完全解耦。
- watchdog 比内部稳定捕获超时多 5 秒收尾余量，避免超时边界竞态。
- 第一次运行不再先等待 1.2 秒，而是立即启动首次完整扫描。
- 新增托盘图标；右键可重启恢复、立即扫描、退出，双击执行重启恢复。
- Explorer 重启后监听 `TaskbarCreated` 自动恢复托盘图标。
- 扫描暂停通知改用 Windows 通知区域的系统通知，不再使用自绘右下角 STATIC 窗口。
- 仍保持绿色三文件运行结构：EXE + 自动生成 config.ini + sessions.dat。


## v0.2.3 修复

- 确认 v0.2.2 扫描器存在过度严格判定：独立顶层 Explorer HWND 对照和整个序列化快照 hash 比较都会把 Windows 11 Explorer 的正常瞬态状态误判为“不完整扫描”。
- 移除 `SnapshotCoversAllTopLevelExplorerWindows()` 作为扫描硬条件。
- `Shell.Application.Windows()` 改为窗口/标签会话唯一事实来源；同 HWND 继续作为标签组。
- 新增语义稳定比较：按 HWND 匹配窗口，并按 `kind + 规范化位置` 多重集合匹配标签；忽略 placement 与枚举顺序。
- `Shell.Windows().Count` 在同一轮捕获前后变化时，本轮作废并重试，用来覆盖增删标签/窗口的瞬态。
- 单轮 COM/路径读取瞬态失败不再立刻熔断；在独立扫描超时内持续重试。
- sessions.dat ERSNAP2 / ERHIST2 格式完全不变，旧历史兼容。


## v0.2.5 关键修正

用户实测 v0.2.4 在 6 组/19 标签恢复后全部最终校验失败，窗口会创建后立即被程序关闭。根因之一是恢复器擅自使用 COM identity + 严格整组 Repair/Validate，并在失败时主动关闭整组窗口。v0.2.5 将标签恢复原语回到 Mine_Exp：以 `(HWND, LocationURL)` 前后差集识别新标签，再 `Navigate2`；对“新标签初始 URL 与已有标签重复”的情况仅增加 count 增长后取最后项的非破坏补强。整组校验从破坏性动作降为只读报告，任何失败均不得关闭已经恢复的 Explorer 窗口。

- 安全保护：周期扫描发现当前为 0 个 Explorer 窗口时不推进历史；若已有有效历史且当前没有 Explorer 窗口，救援直接使用最近有效历史，不先写入空快照。


## v0.2.7 窗口位置/尺寸恢复修正

用户实测 v0.2.5 已能按原标签页组恢复 6 组/19 标签，但所有新窗口的位置均未恢复到原位置，并且位置不可信时也没有执行既定“主显示器中央常规尺寸”规则。

根因与修正：

1. 旧实现只持久化 `WINDOWPLACEMENT`。微软定义中 `rcNormalPosition` 属于 workspace coordinates，不是通用 screen coordinates；虽然 `GetWindowPlacement/SetWindowPlacement` 理论上应成对使用，但 Win11 Explorer 新窗口建立后还会异步执行自身 frame/layout 初始化，单次位置写入容易被覆盖。
2. v0.2.7 对非最小化窗口额外调用 `GetWindowRect()`，把真实屏幕坐标矩形保存为 `WindowState.screenRect`。
3. 快照 payload 版本从 2 升级到 3；反序列化同时接受 v2/v3。旧五槽历史继续有效，但 v2 记录没有 `screenRect`，恢复位置按“不确定”处理并居中，不再硬套旧坐标。
4. 恢复普通窗口时先 `ShowWindow(SW_RESTORE)`，再 `SetWindowPos()` 使用真实 screen coordinates；最大化窗口最后重新 `ShowWindow(SW_SHOWMAXIMIZED)`。
5. 所有窗口/标签组全部恢复后等待 650 ms，再对全部已恢复 HWND 做第二次位置写回，防止 Explorer 异步初始化覆盖第一遍。
6. 最小化窗口不信任 GetWindowRect/COM 几何；若没有可靠屏幕矩形，恢复成主显示器工作区中央、合理常规尺寸的普通窗口，避免角落小窗。

数据安全：本改动不改变标签扫描/分组/恢复主链，不删除旧 sessions.dat，不引入新文件、注册表、日志或运行时依赖。
