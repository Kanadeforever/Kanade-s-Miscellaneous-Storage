## v0.2.11 代码复核结论

本轮开始前重新复核 v0.2.10 全部源码，确认恢复稳定主链位于 `explorer.cpp`，本轮没有修改其：

- Mine_Exp 风格 `Shell.Application.Windows()` 捕获原语；
- `(HWND, LocationURL)` 新标签识别；
- `ShellTabWindowClass / WM_COMMAND 0xA21B` 标签创建；
- 首窗口 1200 ms 稳定闸门；
- bootstrap 单标签启动窗口复用/全成功后残留清理；
- `GetWindowRect` 窗口位置恢复和最终二次回写。

本轮功能变更集中在：

- `src/app.cpp`：后台扫描故障状态机、隔离重试、跨进程会话写入锁、托盘“重启本软件”；
- `src/core.cpp / src/core.h`：连续失败通知阈值配置；
- `src/winmini.h`：补充 `WAIT_ABANDONED / ReleaseMutex` 最小 Win32 声明；
- `tools/kernel32.def`：为交叉构建导入库补充 `ReleaseMutex`。

`explorer.cpp / snapshot.cpp / ole_dispatch.cpp` 以及图标/Manifest 资源均保持 v0.2.10 不变。

## v0.2.11 重点实机验收

### A. 普通扫描失败不再永久停扫

1. 长期运行观察；
2. 若出现某一轮 Shell COM 扫描失败/超时，托盘状态应进入“扫描异常/隔离自动重试”；
3. 不应再出现“从此永久停止扫描，必须重启恢复后才继续”的旧行为；
4. 后续成功扫描后，托盘应自动回到“后台保护中”；
5. `sessions.dat` 最近有效历史不能被失败轮覆盖。

### B. 连续失败通知节流

默认：

```ini
NotifyAfterConsecutiveFailures=3
```

- 第 1、2 次连续失败静默；
- 第 3 次失败通知一次；
- 第 4、5……次连续失败不重复刷通知；
- 中间只要成功一次，计数清零；下一轮新的连续故障达到 3 次时可以再次通知。

### C. 真正 watchdog 超时后的隔离重试

若正常扫描线程超过 `TimeoutMilliseconds`：

- 当前扫描结果必须作废；
- 主守护不能继续堆叠新的 COM 工作线程；
- 后续周期使用一次性 `/capture-once` 子进程重试；
- 子进程超时可被结束；
- 原线程若稍后自行返回，其旧结果不得写入历史；
- 原线程返回后应恢复普通线程扫描。

### D. 托盘“重启 Explorer Rescue”

- 托盘第一项显示“重启 Explorer Rescue”；
- 双击托盘图标也执行重启本软件；
- 不应重启 `explorer.exe`；
- 旧实例退出、释放单实例互斥量后再启动新实例；
- 新实例不得因为“第二实例语义”误触发 Explorer 救援；
- 若隔离 `/capture-once` 子进程正在运行，自重启应先等待它结束/超时回收，不留下孤儿进程；
- `Win + Shift + E` 和再次运行 EXE 仍然负责 Explorer 重启恢复。

### E. 恢复主链回归

使用 v0.2.10 已通过场景再次确认：

- 标签组数量和组合不变；
- 标签路径正确；
- bootstrap 不残留额外“此电脑/Home”窗口；
- 原窗口位置恢复；
- 位置未知时居中兜底；
- 任务栏恢复速度不退化。

## 当前环境限制

当前构建容器不是 Windows 11 Explorer 环境，因此无法在容器内真实触发 Shell COM 卡顿、`ShellTabWindowClass` 或任务栏/Explorer 动态恢复。动态结论仍以用户 Windows 11 实机验收为准。
