# Explorer Rescue v0.2.11 工具说明

源码包内 `tools` 目录只包含构建辅助内容，不参与程序运行。当前工具版本已随 v0.2.11 全量重新核对。

## make_resources.py

用途：重新生成 Explorer Rescue 图标资源与 Win32 `.res` 文件。

输出：

```text
src\resources\ExplorerRescue.png
src\resources\ExplorerRescue.ico
src\resources\ExplorerRescue.res
```

功能：

- 使用 Pillow 绘制 Explorer Rescue 文件夹/标签页/恢复箭头图标；
- 生成 16/20/24/32/40/48/64/128/256 像素 ICO；
- 将图标打包为 Win32 RT_ICON / RT_GROUP_ICON；
- 写入 PerMonitorV2、Windows 兼容性和 longPathAware Manifest；
- 最终生成可直接交给 MSVC linker 的 `ExplorerRescue.res`。

正常构建**不需要运行这个脚本**，源码包已经带当前稳定资源。只有需要重新设计/生成图标资源时才运行。

依赖：Python + Pillow。

## *.def

`kernel32.def / user32.def / ole32.def / oleaut32.def / shell32.def` 是交叉构建与静态验收使用的最小 Windows 导入定义。

用途：

1. 在没有完整 Windows SDK `.lib` 的环境中生成最小导入库；
2. 让 `clang-cl + lld-link` 可以对源码做独立交叉编译；
3. 用于复核最终 PE 是否意外引入 CRT、额外 DLL 或错误的 `Interlocked*` 导入。

Windows + Visual Studio 正常构建直接使用 Windows SDK 自带系统 `.lib`，不需要手工处理这些 `.def`。

v0.2.11 的 `kernel32.def` 新增 `ReleaseMutex`，仅用于跨进程串行化 `sessions.dat` 写入；它仍然来自系统 `KERNEL32.dll`，没有新增 DLL。

## v0.2.11 与工具的关系

本轮没有新增任何运行时工具。扫描超时后的隔离重试使用的仍然是**同一个 `ExplorerRescue.exe /capture-once`**，不会释放第二个辅助 EXE，也不会增加运行目录文件。

因此实际运行目录仍严格只有：

```text
ExplorerRescue.exe
config.ini
sessions.dat
```

## 安全说明

这些构建工具：

- 不联网；
- 不修改注册表；
- 不接触用户 `sessions.dat`；
- 不参与常驻运行；
- 不会被打包成额外运行时依赖。
